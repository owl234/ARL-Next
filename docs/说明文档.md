# ARL-Next 升级改造方向说明文档

**版本**：v1.0
**日期**：2026-09-28
**状态**：草案
**目标**：为 ARL-Next 从当前 Flask + MongoDB + RabbitMQ 单一技术栈，演进为 FastAPI + 多数据库 + 多消息队列的现代化架构提供设计说明。

------

## 一、背景与目标

### 1.1 现状

ARL-Next 当前技术栈：

| 层次     | 当前技术            | 约束                                   |
| :------- | :------------------ | :------------------------------------- |
| Web 框架 | Flask + Flask-RestX | WSGI 同步模型，高并发受限              |
| 主存储   | MongoDB             | 单一数据库，无法承载关系型/图/时序数据 |
| 消息队列 | RabbitMQ            | 单一 MQ，无法按业务特性选型            |
| 任务调度 | Celery              | 与 RabbitMQ 强绑定                     |
| 前端     | Vue 3 + Vite        | 保持不变                               |

### 1.2 升级目标

1. **Web 框架**：Flask → FastAPI，获得异步 I/O 与自动 API 文档能力
2. **多数据库**：支持 MongoDB / PostgreSQL / Neo4j / InfluxDB 按业务场景选型
3. **多消息队列**：支持 RabbitMQ / Kafka / Redis Streams 按业务特性选型
4. **平滑迁移**：新老架构可并行运行，不影响现有生产环境

### 1.3 非目标

- 不改动前端技术栈
- 不迁移历史数据（提供双写方案过渡）
- 不改变现有 API 契约（保持前端零改动）

## 三、FastAPI 迁移方案

### 3.1 迁移价值

| 维度          | Flask       | FastAPI       | 提升                    |
| :------------ | :---------- | :------------ | :---------------------- |
| **并发模型**  | WSGI 同步   | ASGI 异步     | I/O 密集场景 5-8 倍吞吐 |
| **类型安全**  | 手动校验    | Pydantic 自动 | 减少 60% 参数校验代码   |
| **API 文档**  | Flask-RestX | OpenAPI 自动  | 零维护成本              |
| **依赖注入**  | 需手动实现  | 原生 Depends  | 代码更清晰              |
| **WebSocket** | 需扩展      | 原生支持      | 实时推送更简单          |

### 3.2 关键迁移策略

### 3.3 迁移风险与对策

| 风险                               | 对策                                                         |
| :--------------------------------- | :----------------------------------------------------------- |
| **异步陷阱**：阻塞调用拖慢事件循环 | 所有 DB/HTTP 操作使用异步驱动（Motor/asyncpg/httpx）         |
| **Celery 与 asyncio 不兼容**       | 用 `arq` / `taskiq` 替代，或通过 `asyncio.run_coroutine_threadsafe` 桥接 |
| **现有中间件不可用**               | 逐一替换为 ASGI 原生方案                                     |
| **测试覆盖不足**                   | 先补齐测试再迁移                                             |
| **团队学习成本**                   | 先在新模块试点，逐步推广                                     |

### 3.4 框架选型建议

| 组件            | 推荐                    | 理由                   |
| :-------------- | :---------------------- | :--------------------- |
| **Web 框架**    | FastAPI                 | 生态最成熟，社区最活跃 |
| **ASGI 服务器** | Uvicorn + Gunicorn      | 生产环境标配           |
| **数据校验**    | Pydantic v2             | 性能比 v1 提升 5-50 倍 |
| **配置管理**    | pydantic-settings       | 类型安全的配置         |
| **ORM/ODM**     | SQLAlchemy 2.0 + Beanie | 见第四章               |
| **任务队列**    | arq 或 taskiq           | 原生 asyncio 支持      |
| **HTTP 客户端** | httpx                   | 支持异步               |

### 4.6 图模型示例（Neo4j）

python

```
from neo4j import AsyncGraphDatabase


class AssetGraphRepository:
    """资产图仓库"""

    def __init__(self, driver: AsyncGraphDatabase):
        self.driver = driver

    async def add_asset_relation(
        self, ip: str, cve_id: str, port: int,
    ):
        """建立 IP → CVE 关系"""
        cypher = """
        MERGE (a:Asset {ip: $ip})
        MERGE (v:Vulnerability {cve_id: $cve_id})
        MERGE (a)-[r:VULNERABLE_TO {port: $port}]->(v)
        RETURN r
        """
        async with self.driver.session() as session:
            return await session.run(
                cypher, ip=ip, cve_id=cve_id, port=port)

    async def find_shared_vulns(self, cve_id: str):
        """发现共享同一 CVE 的所有资产"""
        cypher = """
        MATCH (a:Asset)-[:VULNERABLE_TO]->(v:Vulnerability)
        WHERE v.cve_id = $cve_id
        RETURN a.ip AS ip, a.hostname AS hostname
        """
        async with self.driver.session() as session:
            result = await session.run(cypher, cve_id=cve_id)
            return await result.data()
```



### 4.7 时序模型示例（InfluxDB）

python

```
from influxdb_client.client.influxdb_client_async import (
    InfluxDBClientAsync)


class MetricRepository:
    """监控指标仓库"""

    def __init__(self, client: InfluxDBClientAsync,
                 org: str, bucket: str):
        self.client = client
        self.org = org
        self.bucket = bucket

    async def write_scan_metric(
        self, asset_ip: str, duration: float,
    ):
        """写入扫描耗时"""
        from influxdb_client import Point
        point = (Point("scan_metrics")
                 .tag("asset_ip", asset_ip)
                 .field("duration_ms", duration))
        await self.client.write_api().write(
            bucket=self.bucket, record=point)

    async def query_avg_duration(self, asset_ip: str, hours: int = 24):
        """查询近 24 小时平均扫描耗时"""
        query = f'''
        from(bucket: "{self.bucket}")
            |> range(start: -{hours}h)
            |> filter(fn: (r) => r._measurement == "scan_metrics")
            |> filter(fn: (r) => r.asset_ip == "{asset_ip}")
            |> mean()
        '''
        result = await self.client.query_api().query(query)
        return result
```



### 4.8 数据一致性方案

多数据库场景下的一致性问题：

| 方案            | 适用场景     | 实现方式                     |
| :-------------- | :----------- | :--------------------------- |
| **Saga 模式**   | 跨服务长事务 | 补偿事务 + 事件驱动          |
| **事件溯源**    | 需要审计追溯 | 事件日志 + 物化视图          |
| **双写 + 对账** | 主从同步     | 写主库 + 异步同步 + 定时校验 |
| **CDC**         | 实时同步     | Debezium 捕获变更 → Kafka    |

**推荐方案**：主数据（MongoDB）→ CDC 捕获变更 → 同步至分析库（Neo4j/ES）。

### 5.3 统一接口设计

python

```
from abc import ABC, abstractmethod
from typing import Callable, Awaitable


class MQClient(ABC):
    """消息队列统一接口"""

    @abstractmethod
    async def publish(
        self, topic: str, message: dict, **kwargs,
    ) -> None:
        """发布消息"""
        ...

    @abstractmethod
    async def subscribe(
        self, topic: str,
        handler: Callable[[dict], Awaitable[None]],
    ) -> None:
        """订阅消息"""
        ...

    @abstractmethod
    async def close(self) -> None:
        ...


class RabbitMQClient(MQClient):
    """RabbitMQ 实现"""

    def __init__(self, url: str):
        import aio_pika
        self.url = url
        self.connection = None
        self.channel = None

    async def connect(self):
        import aio_pika
        self.connection = await aio_pika.connect_robust(
            self.url)
        self.channel = await self.connection.channel()

    async def publish(self, topic, message, **kwargs):
        import json
        body = json.dumps(message).encode()
        await self.channel.default_exchange.publish(
            aio_pika.Message(body=body),
            routing_key=topic)

    async def subscribe(self, topic, handler):
        queue = await self.channel.declare_queue(
            topic, durable=True)
        async with queue.iterator() as it:
            async for msg in it:
                async with msg.process():
                    import json
                    data = json.loads(msg.body)
                    await handler(data)


class KafkaClient(MQClient):
    """Kafka 实现"""

    def __init__(self, bootstrap_servers: str):
        self.bootstrap_servers = bootstrap_servers
        self.producer = None

    async def connect(self):
        from aiokafka import AIOKafkaProducer
        self.producer = AIOKafkaProducer(
            bootstrap_servers=self.bootstrap_servers)
        await self.producer.start()

    async def publish(self, topic, message, **kwargs):
        import json
        body = json.dumps(message).encode()
        await self.producer.send_and_wait(topic, body)
```

### 5.5 任务队列迁移

从 Celery 迁移到原生 asyncio 方案：

| Celery 功能       | 替代方案          | 说明                      |
| :---------------- | :---------------- | :------------------------ |
| `@task` 装饰器    | `arq` 或 `taskiq` | 原生 asyncio              |
| `celery beat`     | `arq` 内置 cron   | 无需独立进程              |
| `chain` / `group` | 手写工作流        | 或用 `taskiq` 的 pipeline |
| `rate_limit`      | `aiolimiter`      | 令牌桶算法                |
| `retry`           | 装饰器实现        | 简单重试逻辑              |

### 5.6 消息可靠性

| 级别              | 实现方式        | 适用场景   |
| :---------------- | :-------------- | :--------- |
| **At-most-once**  | 自动 ack        | 日志、监控 |
| **At-least-once** | 手动 ack + 重试 | 大多数业务 |
| **Exactly-once**  | 幂等消费 + 事务 | 支付、账单 |

**推荐**：**At-least-once + 幂等消费**，通过消息 ID + Redis SETNX 实现去重。

## 十、总结与建议

### 10.1 核心建议

## 三、FastAPI 迁移方案

### 3.1 迁移价值

| 维度          | Flask       | FastAPI       | 提升                    |
| :------------ | :---------- | :------------ | :---------------------- |
| **并发模型**  | WSGI 同步   | ASGI 异步     | I/O 密集场景 5-8 倍吞吐 |
| **类型安全**  | 手动校验    | Pydantic 自动 | 减少 60% 参数校验代码   |
| **API 文档**  | Flask-RestX | OpenAPI 自动  | 零维护成本              |
| **依赖注入**  | 需手动实现  | 原生 Depends  | 代码更清晰              |
| **WebSocket** | 需扩展      | 原生支持      | 实时推送更简单          |

### 4.6 图模型示例（Neo4j）

```
from neo4j import AsyncGraphDatabase


class AssetGraphRepository:
    """资产图仓库"""

    def __init__(self, driver: AsyncGraphDatabase):
        self.driver = driver

    async def add_asset_relation(
        self, ip: str, cve_id: str, port: int,
    ):
        """建立 IP → CVE 关系"""
        cypher = """
        MERGE (a:Asset {ip: $ip})
        MERGE (v:Vulnerability {cve_id: $cve_id})
        MERGE (a)-[r:VULNERABLE_TO {port: $port}]->(v)
        RETURN r
        """
        async with self.driver.session() as session:
            return await session.run(
                cypher, ip=ip, cve_id=cve_id, port=port)

    async def find_shared_vulns(self, cve_id: str):
        """发现共享同一 CVE 的所有资产"""
        cypher = """
        MATCH (a:Asset)-[:VULNERABLE_TO]->(v:Vulnerability)
        WHERE v.cve_id = $cve_id
        RETURN a.ip AS ip, a.hostname AS hostname
        """
        async with self.driver.session() as session:
            result = await session.run(cypher, cve_id=cve_id)
            return await result.data()
```



### 4.7 时序模型示例（InfluxDB）

```
from influxdb_client.client.influxdb_client_async import (
    InfluxDBClientAsync)


class MetricRepository:
    """监控指标仓库"""

    def __init__(self, client: InfluxDBClientAsync,
                 org: str, bucket: str):
        self.client = client
        self.org = org
        self.bucket = bucket

    async def write_scan_metric(
        self, asset_ip: str, duration: float,
    ):
        """写入扫描耗时"""
        from influxdb_client import Point
        point = (Point("scan_metrics")
                 .tag("asset_ip", asset_ip)
                 .field("duration_ms", duration))
        await self.client.write_api().write(
            bucket=self.bucket, record=point)

    async def query_avg_duration(
        self, asset_ip: str, hours: int = 24,
    ):
        """查询近 24 小时平均扫描耗时"""
        query = f'''
        from(bucket: "{self.bucket}")
            |> range(start: -{hours}h)
            |> filter(fn: (r) => r._measurement == "scan_metrics")
            |> filter(fn: (r) => r.asset_ip == "{asset_ip}")
            |> mean()
        '''
        result = await self.client.query_api().query(query)
        return result
```

| 方案            | 适用场景     | 实现方式                     |
| :-------------- | :----------- | :--------------------------- |
| **Saga 模式**   | 跨服务长事务 | 补偿事务 + 事件驱动          |
| **事件溯源**    | 需要审计追溯 | 事件日志 + 物化视图          |
| **双写 + 对账** | 主从同步     | 写主库 + 异步同步 + 定时校验 |
| **CDC**         | 实时同步     | Debezium 捕获变更 → Kafka    |

**推荐方案**：主数据（MongoDB）→ CDC 捕获变更 → 同步至分析库（Neo4j/ES）。

### 5.3 统一接口设计

python

```
from abc import ABC, abstractmethod
from typing import Callable, Awaitable


class MQClient(ABC):
    """消息队列统一接口"""

    @abstractmethod
    async def publish(
        self, topic: str, message: dict, **kwargs,
    ) -> None:
        """发布消息"""
        ...

    @abstractmethod
    async def subscribe(
        self, topic: str,
        handler: Callable[[dict], Awaitable[None]],
    ) -> None:
        """订阅消息"""
        ...

    @abstractmethod
    async def close(self) -> None:
        ...


class RabbitMQClient(MQClient):
    """RabbitMQ 实现"""

    def __init__(self, url: str):
        self.url = url
        self.connection = None
        self.channel = None

    async def connect(self):
        import aio_pika
        self.connection = await aio_pika.connect_robust(
            self.url)
        self.channel = await self.connection.channel()

    async def publish(self, topic, message, **kwargs):
        import json
        import aio_pika
        body = json.dumps(message).encode()
        await self.channel.default_exchange.publish(
            aio_pika.Message(body=body),
            routing_key=topic)

    async def subscribe(self, topic, handler):
        queue = await self.channel.declare_queue(
            topic, durable=True)
        async with queue.iterator() as it:
            async for msg in it:
                async with msg.process():
                    import json
                    data = json.loads(msg.body)
                    await handler(data)


class KafkaClient(MQClient):
    """Kafka 实现"""

    def __init__(self, bootstrap_servers: str):
        self.bootstrap_servers = bootstrap_servers
        self.producer = None

    async def connect(self):
        from aiokafka import AIOKafkaProducer
        self.producer = AIOKafkaProducer(
            bootstrap_servers=self.bootstrap_servers)
        await self.producer.start()

    async def publish(self, topic, message, **kwargs):
        import json
        body = json.dumps(message).encode()
        await self.producer.send_and_wait(topic, body)
```



### 5.4 技术选型

| MQ                | Python 异步客户端 | 推荐理由             |
| :---------------- | :---------------- | :------------------- |
| **RabbitMQ**      | aio-pika          | 官方维护、API 友好   |
| **Kafka**         | aiokafka          | 成熟的异步实现       |
| **Redis Streams** | redis.asyncio     | 内置、零依赖         |
| **NATS**          | nats-py           | 云原生、轻量         |
| **Pulsar**        | pulsar-client     | 多租户、支持多种模式 |

### 5.5 任务队列迁移

从 Celery 迁移到原生 asyncio 方案：

| Celery 功能       | 替代方案          | 说明                      |
| :---------------- | :---------------- | :------------------------ |
| `@task` 装饰器    | `arq` 或 `taskiq` | 原生 asyncio              |
| `celery beat`     | `arq` 内置 cron   | 无需独立进程              |
| `chain` / `group` | 手写工作流        | 或用 `taskiq` 的 pipeline |
| `rate_limit`      | `aiolimiter`      | 令牌桶算法                |
| `retry`           | 装饰器实现        | 简单重试逻辑              |

### 5.6 消息可靠性

| 级别              | 实现方式        | 适用场景   |
| :---------------- | :-------------- | :--------- |
| **At-most-once**  | 自动 ack        | 日志、监控 |
| **At-least-once** | 手动 ack + 重试 | 大多数业务 |
| **Exactly-once**  | 幂等消费 + 事务 | 支付、账单 |

**推荐**：**At-least-once + 幂等消费**，通过消息 ID + Redis SETNX 实现去重。

## 十、总结与建议

### 10.1 核心建议

1. **不追求一步到位**：新老并行、渐进迁移，避免全量重写风险
2. **不追求技术前沿**：优先选择成熟稳定的方案（FastAPI + Motor + aio-pika）
3. **不追求完美设计**：先跑通 MVP，再逐步优化
4. **重视团队能力**：异步编程需要时间沉淀，要给团队学习空间
5. **保持 API 契约**：前端零改动是降低风险的关键

### 10.2 决策建议

| 场景                       | 建议                               |
| :------------------------- | :--------------------------------- |
| **团队 < 5 人**            | 暂不迁移，保持 Flask 单栈          |
| **团队 5-10 人**           | 新模块用 FastAPI，老模块保持 Flask |
| **团队 > 10 人**           | 系统性迁移，采用渐进式路线         |
| **业务稳定、无性能压力**   | 不迁移，专注业务功能               |
| **业务增长快、并发压力大** | 优先迁移，尽快享受异步优势         |

### 10.3 最终目标

构建一个**多数据库、多消息队列、全异步、可观测**的现代化安全运营平台，为未来 3-5 年的业务发展提供坚实的技术底座。
